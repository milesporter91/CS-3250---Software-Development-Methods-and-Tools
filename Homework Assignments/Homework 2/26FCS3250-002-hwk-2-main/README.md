# Instructions: Part 1 

A new home security software project is being developed to support the door-to-door sales team. The team needs a system that can:

* List potential customers using publicly available data (e.g., number of rooms, presence of a garage).
* Help salespeople determine the most suitable security system for each customer using a questionnaire.
* Run on mobile devices with large screens.

Based on this description, create 10 high-level requirements for the sales system:

* 4 user functional requirements (what the system should do for users)
* 4 user non-functional requirements (how well the system should perform)
* 2 system requirements (technical or environmental constraints)

```
User Functional Requirements

1. The system should allow salespeople to view a list of potential customers based on publicly available property information.
2. The system should display relevant property details for each potential customer, such as the number of rooms and whether the property has a garage.
3. The system should provide a questionnaire that salespeople can complete with potential customers to identify their home security needs.
4. The system should recommend a suitable security system based on the customer’s property information and questionnaire responses.

User Non-Functional Requirements

5. The system should provide an interface that is easy for salespeople to learn and navigate.
6. The system should display customer and property information quickly enough to support salespeople during door-to-door interactions.
7. The system should present information in a clear and readable format suitable for use on large-screen mobile devices.
8. The system should reliably save questionnaire responses so that salespeople do not lose information while working with a customer.

System Requirements

9. The system should be compatible with large-screen mobile devices used by the sales team.
10. The system should obtain potential-customer property information only from publicly available data sources.
```
